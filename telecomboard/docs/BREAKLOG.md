# BREAKLOG

These are real failures I hit while building Switchboard. Each entry lists the symptom, how it was caught, the cause, the fix, and the test that now guards against it.

| # | Symptom | Detected by | Root cause | Fix | Regression guard |
|---|---|---|---|---|---|
| 1 | First demo run crashed: "refusing to persist secret-like value into session state" | Session-state validator (`save_state`) | The high-entropy secret detector split tokens on whitespace only, so `"subscriber:S-88123",` looked like a random password (mixed case + digits + symbols) | Tokenize on punctuation and require at least 2 lowercase, 2 uppercase and 2 digits | `test_leak_canaries_zero`, every scenario test |
| 2 | Knowledge answers silently missing from S1 and S5 | Demo output had no MOP citation | The tool-level policy check asked about `document:*` with no classification. The PDP treated "no classification" as not allowed, so every document search was denied | Treat a missing classification as a capability probe. Per-document classification is still enforced inside the SQL query | `test_s1_*`, `test_new_tools_respect_policy` |
| 3 | Risk of deadlock in idg-sync | Code review while writing the worker | The worker held `BEGIN IMMEDIATE` on the platform DB while the PDP wrote tuples on a second connection to the same file (SQLite allows only one writer) | Single-leader lock plus a short transaction per row. Publishes are idempotent | `test_deny_by_default_during_sync_lag` |
| 4 | Text-to-SQL execution accuracy dropped to 0.857 at scale 2000 (1.0 at scale 400) | Eval gate (`run_evals.py`) | The validator adds `LIMIT 200` to generated SQL, but the gold SQL was run without a limit. The two result sets differed only when more than 200 rows matched | Pass gold SQL through the same validator before comparing | `test_eval_gate` |
| 5 | "Next day" demo returned HTTP 401 | Demo script | Moving the app clock forward made new JWTs look issued in the future to PyJWT, which uses the real clock | S6 now uses a new session ID, so memory is exercised without shifting time | `test_s6_memory_with_read_time_reauth` |
| 6 | MCP servers failed to import | Adapter smoke test | `mcp` 2.x renamed `FastMCP` to `MCPServer` | Pinned `mcp>=1.9,<2` and recorded the decision in ADR-009 | `test_mcp_servers_expose_annotated_tools_and_require_auth` |
| 7 | Hypothesis fuzzing produced `SELECT customer_id name`, which the SQL validator accepted | `test_validator_fuzz_never_allows_forbidden` | Any identifier used as an alias became allowed, so an alias named after a PII column (`name`) could be referenced later and slip past the column check. The canon views still withheld the data, so nothing leaked, but one defense layer was bypassed | Reject aliases that reuse a blocked (PII/secret) column name | `test_validator_rejects[...alias...]` + fuzz test |
| 8 | "How do I replace an ONT?" answered with "1. Replace fan tray" from the poisoned doc DOC-POISON-1 | Capturing demo outputs for GUIDE.md | Only the poisoned *section* was quarantined, so the clean-looking Procedure section of the same doc stayed searchable. Glossary expansion ("ONT (optical network terminal)") also added noisy terms, and unstemmed full-text search could not match "replace" to "replacement" | Quarantine the whole document when any section is poisoned. Index title + section with a porter stemmer. Search with the user's own words. Answer with the top doc's sections in order | `test_mop_answer_uses_correct_document` |
